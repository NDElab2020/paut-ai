# 결함 기록 양식(엑셀) 만들기

전문가가 OmniPC 로 판독한 지시를 적는 엑셀 양식 두 가지를 만듭니다(라벨링 0단계).

| 파일 | 누구에게 | 내용 |
|---|---|---|
| `계획_라벨링/기록양식_v1.xlsx` | **판독자 (기본 배포본)** | 판독자용·블라인드. '물리결함' 시트가 비어 있고, '판독자' 시트의 판독 단계 = 블라인드 |
| `계획_라벨링/기록양식_v1_대조용.xlsx` | 대조 단계·Level III 만 | 결함정보.docx 11건(종류·위치)이 '물리결함' 시트에 들어 있음. 판독 단계 = 설계값 대조. **블라인드 판독자에게 주지 않습니다** |

칸은 앱 코드 한 곳, `src/shared/labels/columns.ts` 에서만 정합니다. 엑셀을 손으로 고치지 말고, 칸을 바꿀 때는 columns.ts 를 고친 뒤 아래 명령으로 다시 만듭니다.

## 다시 만드는 명령

`app/` 에서 실행합니다. 새로 설치할 것은 없습니다(python3 + openpyxl 3.1).

```sh
cd 10_데이터관리툴/app

# 1) 칸 정의 → JSON (테스트가 칸 검사를 하고 JSON 을 씀)
PAUT_LABEL_COLUMNS_OUT="$TMPDIR/label_columns.json" npx vitest run tests/labels/templateColumns.test.ts

# 2) JSON → 판독자용(블라인드) 양식
python3 scripts/label-template/make_template.py \
  --columns "$TMPDIR/label_columns.json" --blind \
  --out "../계획_라벨링/기록양식_v1.xlsx"

# 3) JSON → 대조용 양식 (결함정보.docx 와 먼저 대조)
python3 scripts/label-template/make_template.py \
  --columns "$TMPDIR/label_columns.json" \
  --docx "../../06_원시데이터/02_라벨완료/X3_12T-SV/00_결함정보.docx" \
  --out "../계획_라벨링/기록양식_v1_대조용.xlsx"
```

- `--docx` 는 선택입니다. 주면 `prefill_x3.json` 의 물리결함 11건이 결함정보.docx 글(종류·위치)과 같은지 먼저 봅니다.
- **덮어쓰기 보호**: `--out` 이 이미 있고 미리 채운 값과 다른 칸(사람이 적은 값)이 있으면 덮어쓰지 않고 멈춥니다. 전문가가 그 파일에 적고 있을 수 있기 때문입니다. 덮어써도 되는 것을 확인했을 때만 `--force` 를 더합니다.
- 생성기는 같은 폴더의 임시 파일(`.<이름>.만드는중.xlsx`)에 저장하고 다시 열어 확인한 뒤에만 `--out` 으로 바꿔 넣습니다. 확인이 실패하면 `--out` 은 그대로입니다.
- 지침서(`계획_라벨링/지침서_v*.md`)가 없으면 만들지 않습니다(안내 시트에 지침서 경로가 들어가야 함).
- 엑셀이 열려 있으면 저장이 실패합니다. 닫고 다시 실행합니다.

## 파일

| 파일 | 내용 |
|---|---|
| `make_template.py` | 생성기. 시트 '안내' + 데이터 시트 6개(columns.ts 순서: 판독자·파일·지시·검토구간·물리결함·작업시간) + 숨긴 '목록' 시트. 만든 뒤 다시 열어 시트 순서·머리글·칸마다 유효성(드롭다운·숫자 범위·끝 ≥ 시작·두께 이하)·조건부 필수 서식·머리글 메모·미리 채운 값·목록 값·안내 문구('작성 중' 없음, 판독자용에 결함정보 문구 없음)·문서 속성을 확인 |
| `prefill_x3.json` | 미리 채울 값. '판독자' 시트 = 지침서 버전 v1(라벨러 ID 는 전문가가 적음, 판독 단계는 생성기가 양식 종류대로), '파일' 시트 = X3 12T-SV 4개 파일 이름·시편 ID(앱 제안값)·두께 12 mm·가설 정렬(스캔 0 = 판 끝, +1), '물리결함' 시트 = 결함정보.docx 11건(대조용에만). 열거 칸은 코드로 적고 생성기가 표시 이름으로 바꿈. `_` 로 시작하는 칸은 메타데이터, `_partial` 줄은 필수 칸 일부를 비워 둔 줄 |
| `../../tests/labels/templateColumns.test.ts` | 칸 검사(시트 이름·머리글이 엑셀에서 쓸 수 있는지, 드롭다운 값 → 코드 되찾기, prefill 이 스키마 검사를 통과하는지) + `PAUT_LABEL_COLUMNS_OUT` 이 있으면 JSON 쓰기(형식 버전 2: 칸마다 rule·requiredWhen, 시트마다 maxRows) |

## 양식의 모양

- 머리글 1행 = columns.ts 의 한국어 머리글 그대로(앱이 가져올 때 이 글자로 칸을 찾음). 굵게, 1행·A열 고정, 자동 필터.
- 머리글 칸 색: 주황 = 필수, 파랑 = 비워도 됨(앱이 채움), 회색 = 선택. 조건부 필수 칸은 조건이 맞는데 비면 칸이 빨갛게 됨(조건부 서식). 머리글 메모 = 도움말·형식·값·검사·조건·빈 칸 기본값.
- '판독자' 시트는 한 줄(2행)만 씁니다. 라벨러 ID·판독 단계가 이 파일의 모든 줄에 붙어 라벨 세트를 가릅니다(파일 이름으로 가르지 않음).
- 데이터 유효성(2~501행): 열거 칸 = 숨긴 '목록' 시트의 표(이름 붙은 범위 `L_<표 이름>`), 참거짓 = 예/아니오, 다른 시트의 파일명·시편 ID = '파일' 시트 값(목록에 없으면 경고만). 숫자 칸 = 칸마다 범위(columns.ts `rule`), 끝 ≥ 시작, 실제 깊이 ≤ 그 파일 두께('파일' 시트에서 찾음), 게이트 펼친 깊이 ≤ 4 × 두께, 레그 정수 1~4. 시각 칸 = 날짜·시각만, 판독 끝 ≥ 시작. 글자 칸은 글자 형식, 시각 칸은 `yyyy-mm-dd hh:mm`.
- 문서 속성(사용자 지정): `paut.labelForm`, `paut.labelSchemaVersion`, `paut.columnsFingerprint`(칸 정의 JSON sha256 앞 12자), `paut.columnsSource`, `paut.blind`, `paut.readingStage`. 1a 단계 가져오기가 칸 정의가 바뀌었는지 이 지문으로 알 수 있습니다.
- 엑셀(윈도우)에서 쓰는 것을 기준으로 만들었습니다. 다른 시트를 가리키는 검사 수식(VLOOKUP)·조건부 서식이 윈도우·맥 엑셀, 맥 Numbers·LibreOffice 에서 실제로 동작하는지는 아직 화면으로 확인하지 않았습니다.
