# core/labels — 결함 라벨 저장 규칙 · 합치기

저장소는 `catalog.labels`(`core/catalog/labels.ts`, 스키마 v2)입니다. 기록 형식과 검사는 `shared/labels`입니다. 이 폴더는 그 위에 앱 규칙을 얹습니다.

## 저장소 (catalog.labels)

- 테이블: `label_labelers`, `label_records`(지시 기록), `label_observations`(관측 표), `label_review_intervals`(검토 구간), `label_file_alignments`(파일 정렬), `label_physical_defects`(물리 결함, 시편 ID 대소문자 무시), `label_work_events`(작업 이벤트, 추가 전용), `label_conflicts`(충돌 보관), `label_meta`(이 저장소의 복제본 ID·쓰기 횟수), `label_import_marks`(엑셀에서 마지막으로 가져온 줄의 지문).
- 행마다 검사를 통과한 객체 JSON 을 통째로 둡니다. 모르는 칸도 그대로 남습니다. 다른 열은 찾기용입니다.
- 파일과는 sha256 글자로만 잇습니다. FK 가 없어 파일이 없어도 기록은 남습니다.
- 저장하면 이 PC 의 고친 횟수가 1 오릅니다(버전 벡터). 내용이 그대로면 오르지 않습니다.
- 버전 벡터의 칸은 'PC ID:복제본 ID' 입니다(`replica`). 복제본 ID 는 (PC ID, DB 파일 위치)마다 저장소가 무작위로 만듭니다.
  - 한 PC 가 저장소 둘을 쓰거나, DB 를 복사해 다른 곳에서 열거나, PC ID 를 다른 PC 와 같게 바꿔도 칸이 겹치지 않습니다. 그래서 덮어쓰기 대신 충돌로 보입니다.
  - 백업에서 되돌린 DB 는 서비스가 쓰기 횟수(`writeCount`)로 알아채 새 칸으로 바꿉니다(`rotateReplica`, userData/label-replicas.json).
  - 기록의 `pcId`('마지막으로 고친 PC')는 PC ID 그대로입니다.
- groupingId 는 앱 계산 칸입니다. 내용 비교(`sameLabelContent`)에서 빼고, 버전을 올리지 않고 씁니다(`setRecordGrouping`).
- 넘긴 기록의 versions 가 저장된 것과 다르면 `CONFLICT` 입니다. 그사이 다른 곳(가져오기 등)에서 바뀐 것입니다. 다시 열어 고칩니다.
- 기록의 파일·라벨러·지침서 버전·판독 단계는 바꿀 수 없습니다. 새 기록으로 만듭니다.
- 지우기는 삭제 표시입니다. 목록은 기본으로 삭제 표시를 뺍니다(`includeDeleted`).
- 2인 독립 라벨: 목록에 `visibleLabelerId` 를 주면 그 라벨러 세트만 보입니다.
- 라벨 세트 목록(`listLabelSets`): 세트마다 기록 수, 결함 수, 삭제 수, 검토 완료 길이(합집합 mm), 품질 불량·기준 미만 길이, 이 PC 의 파일 연결, 풀지 않은 충돌 수.

## 규칙 (store.ts)

- `saveLabelRecord` · `deleteLabelRecord`: 기록을 만들거나 고치거나 지우면 같은 세트의 겹치는 '검토 완료' 구간을 풉니다(`released`). 옮긴 기록은 옛 위치와 새 위치를 모두 봅니다. 그룹을 모르는 기록은 모든 그룹의 구간을 풉니다.
- 기록을 지우면 그 관측 행도 지움 표시합니다(관측 행은 기록 UUID 로만 이어져, 남으면 다른 지시에 섞일 수 있음).
- `recomputeGrouping`: 시방서 그림 5·6 으로 groupingId 를 다시 매기고 바뀐 기록만 씁니다(버전은 그대로). 검토 구간은 풀지 않습니다. 두께는 인자 → 파일 정렬 → 스캔플랜 순서로 찾습니다. 검수 확정 저장(`labelReview.ts` saveFinal) 때 부릅니다. 엑셀 확정·앱 저장 때는 부르지 않고, 비교는 그때그때 다시 묶습니다(`shared/labels/review/compare.ts` grouping = compute).

## 내보내기 · 가져오기

- `exportLabels(catalog, 범위, { appVersion, pcId })`: 범위는 전체 · 파일(sha256 목록) · 라벨 세트 목록. 삭제 표시와 풀지 않은 충돌 사본도 넣습니다(내 것이 먼저).
- `importLabels(catalog, 글자 또는 객체)`: 검사(`parseLabelExport`) → 한 트랜잭션으로 합치기. 오류가 하나라도 있으면 아무것도 쓰지 않습니다.
  - 같은 UUID 의 기록·검토 구간인데 파일·라벨러·지침서·단계가 다르면 오류입니다(다른 라벨 세트로 옮기지 않음).
  - 작업 이벤트처럼 버전이 없는 단위도, 전에 '내 것'·'둘 다'로 푼 같은 들어온 값은 다시 충돌로 만들지 않습니다.
  - 내 것 없음 → 새로 / 들어온 것이 새것 → 갱신 / 내 것이 새것이거나 같음 → 그대로 / 양쪽에서 따로 고침 → 충돌(내 것을 두고 둘 다 보관).
  - 버전만 갈리고 내용이 같으면 버전만 합칩니다(자동 합침).
  - 같은 파일을 다시 가져와도 결과가 같습니다.
- `resolveLabelConflict(catalog, id, 'mine' | 'theirs' | 'both', { pcId, versionSlot })`: 두 버전을 합치고 1 올려 저장합니다. '들어온 것'은 라벨 세트가 같을 때만 고를 수 있습니다. 그래서 같은 충돌이 되살아나지 않고 다른 PC 로 퍼집니다. '둘 다'는 들어온 쪽에 새 UUID 를 줍니다(지시 기록·검토 구간·작업 이벤트만).
- 다른 PC 가 푼 결과가 들어오면 남은 충돌은 저절로 닫힙니다('superseded').
- 서비스(`core/service/labels.ts`)가 덧붙이는 것: '들어온 것'·'둘 다'는 제출(잠금)한 세트·검수 확정 세트가 있는 파일의 확정 단계·잠긴 시험 파일의 확정 단계 세트에서 `CONFLICT`('내 것'은 됨 — 앱 저장의 guardSet 과 같은 보호). JSON 가져오기는 제출 잠금을 보지 않지만(잠금은 이 저장소에만 있음) 제출한 세트가 바뀌면 경고합니다(`importLabels` 의 `onWrite`). 검수 확정 기록의 출처 칸(`adjudication`)은 앱이 만든 칸이라 '모르는 칸' 경고에서 뺍니다.

## 엑셀 재가져오기 (core/service/labelWorkbook.ts)

엑셀이 그 줄의 원본입니다. 다만 앱·다른 PC 에서 고친 것을 엑셀이 덮지 않도록, 줄마다 '지난번에 가져온 엑셀 줄의 지문과 그때의 versions'(`label_import_marks`)와 견줍니다.

| 저장본 | 엑셀 줄 | 결과 |
|---|---|---|
| 지난 가져오기 뒤 그대로 | 지난번과 같음 | 그대로 |
| 지난 가져오기 뒤 그대로 | 바뀜 | 고침 (스캔 범위가 겹치지 않거나 구분이 바뀌면 '번호가 다른 지시'로 보고 충돌) |
| 앱·다른 PC 에서 고침 | 지난번과 같음 | 이 PC 값 남김 |
| 앱·다른 PC 에서 고침 | 바뀜 | 충돌 (둘 다 보관) |
| 엑셀이 지움 표시함 | 다시 나타남 | 되살림 |
| 앱에서 지움 | 다시 나타남 | 그대로 둠 |
| 엑셀에서 빠짐 | — | 손대지 않은 것만 지움 표시(관측 행도). 고친 것은 남기고 경고 |

- 고칠 때는 엑셀이 아는 칸만 덮습니다(`mergeKnown`). 새 버전 앱이 보낸 모르는 칸은 남습니다.
- 범위: 지시·검토구간·작업시간 줄이 있는 파일과 '파일' 시트에 줄이 있는 파일의 (판독자 · 지침서 · 단계) 라벨 세트입니다.
- 미리보기는 고침·지움 표시·충돌을 목록으로 보이고, '확인했습니다'를 고른 뒤에만 확정합니다.
- 묶어 둔 세트(2026-10-07): 제출(잠금)한 세트, 검수 화면에서 만든 확정 세트가 있는 파일의 확정 단계 세트, 시험 세트가 잠긴 시험 파일의 확정 단계 세트는 새로·고침·지움 표시·충돌 없이 모두 '그대로 둠'이고 미리보기에 이유와 안내가 나옵니다(서비스 `frozenSetJudge`, 미리보기와 확정 때 다시 봄).
- 앱에서 만든 같은 지시가 이미 있으면(무작위 UUID — '설계값 대조 시작' 사본 등) 엑셀 줄을 새로 만들지 않습니다: 지시 기록은 같은 지시 번호, 검토 구간은 같은 구분·그룹·스캔 범위.
- 2인 독립 모드에서는 지금 라벨러의 엑셀만 미리보기·확정합니다(다른 판독자 엑셀은 `INVALID_ARGUMENT`).
